IV screening: what rank_iv() does

Worked on 500 borrowers · candidates = income, utilisation, enquiries, coin_flip · target = default

The goal of this cell: before spending a chart on any single feature, screen every candidate at once down to one ranked table. This is pass 1 of the two-pass workflow — compute IV cheaply for everything, decide keep/drop from the table, and only run plot_woe on the survivors.

Each iv() call internally rebuilds a full woe_table and sums its iv_bin column — you're seeing the single number that computation collapses to.
What changed: One row per feature, each with its IV number. Note coin_flip auto-detected as categorical (it's a string column) while the other three were quantile-binned as numeric — rank_iv does this dtype check for you so you never hand it the wrong flag.
Why: This is the expensive part (one binning + groupby per column) but it's still cheap next to plotting — this loop runs in milliseconds even for 40+ columns; a chart per column would not.

What changed: A band column appears: useless / weak / medium / strong / check leakage, using the fixed Siddiqi cutoffs (0.02, 0.1, 0.3, 0.5).
Why: Raw IV numbers are hard to eyeball in bulk. The band turns a float into a decision-ready label you can filter or sort on.
